### Целевая платформа: Quest 2
Quest 2 — автономный шлем на мобильном чипе Snapdragon XR2. Отсюда ограничения, которые мы закладываем с самого начала:
- **Бюджет кадра:** 72 Гц, то есть ≈ 13,9 мс на кадр. Если не успеваем — картинка дёргается, и игрока укачивает.
- **Геометрия:** до ~100–150 тыс. треугольников в кадре, ~100 draw calls. Low-poly здесь не только стиль, но и требование производительности.
- **Свет:** один направленный источник в реальном времени без теней или запечённый свет (lightmaps); никакой постобработки (bloom, SSAO).
- **Физика:** шаг Fixed Timestep = 1/72 с, чтобы физика совпадала с частотой кадров. Для быстрых объектов (мяч, стрела, кулак) — Continuous collision detection.
- **Контроллеры:** Oculus Touch (профиль уже включён в OpenXR).

### Как запускаем
1. **Разработка — через Quest Link / Air Link.** Шлем подключён к ПК, Unity в режиме Play сразу показывает сцену в шлеме. Сборка не нужна, правки видны за секунды. Платформа Windows, модуль Android для этого не нужен.
2. **Без шлема** — XR Device Simulator: руки управляются мышью и клавиатурой.
3. **Финальная сборка** — APK для Quest 2 (Android, IL2CPP, ARM64, Vulkan — уже выставлено в проекте). Для неё нужно доустановить модуль **Android Build Support** через Unity Hub.

## 2. Выбранные виды спорта

Принцип выбора: каждый режим демонстрирует **свой тип VR-взаимодействия** и **свою физическую модель**, а модели для всех — простые low-poly.

| # | Режим | Тип взаимодействия | Главная физика | Приоритет |
|---|---|---|---|---|
| 1 | **Боулинг** | взять и бросить тяжёлый предмет | масса, трение дорожки, вращение шара (хук), столкновения кеглей | обязательный |
| 2 | **Баскетбол** | точный бросок | расчёт скорости броска по движению руки, отскок (Physics Material), обод/щит | обязательный |
| 3 | **Стрельба из лука** | двуручное натяжение | сила натяжения → начальная скорость, баллистика, стабилизация стрелы по вектору скорости, ветер | обязательный |
| 4 | **Бокс** | удар рукой без предмета | скорость кулака → импульс, груша на шарнире (Joint) | обязательный |
| 5 | **Мини-гольф** | удар инструментом | качение, трение качения, уклоны, препятствия | по возможности (если останется время) |

## 3. Игровые петли (core loop) каждого режима

Общая схема всех режимов: **Подготовка → Попытка → Мгновенная обратная связь (очки, звук, вибрация) → Усложнение → Итог и рекорд → «Ещё раз»**.

### 3.1 Боулинг
- **Петля:** 10 фреймов по 2 броска, классический подсчёт (страйк = 10 + два следующих броска, спэр = 10 + следующий бросок).
- **Мотивация:** таблица очков над дорожкой, рекорд, ачивки «Страйк», «Индюк» (3 страйка подряд).
- **Доп. режим «Испытания»:** заранее расставленные «сплиты» — сбить за один бросок.
- **Физика:** шар 6–7 кг, кегли ~1,5 кг; передняя часть дорожки «смазана» (низкое трение), задняя — сухая, поэтому закрученный шар уходит в хук. Возврат шара — по жёлобу.

### 3.2 Баскетбол
- **Петля:** аркада на 60 секунд. Попадание = 2 очка, из дальней зоны = 3.
- **Мотивация:** серия попаданий подряд даёт множитель ×2/×3; после N очков кольцо начинает двигаться; последние 10 секунд — «огненные мячи» с двойными очками.
- **Физика:** скорость броска считается как среднее по последним кадрам движения контроллера (иначе бросок «дёргается»); упругость мяча, отскок от щита; попадание засчитывается триггером, через который мяч проходит **сверху вниз**.

### 3.3 Стрельба из лука
- **Петля:** волны мишеней: неподвижные → движущиеся → летящие тарелочки; ограниченное число стрел на волну.
- **Мотивация:** очки по кольцам мишени (центр = 10), бонус за дальность, ветер (виден по флажку) меняется каждую волну.
- **Физика:** сила натяжения тетивы ∝ расстоянию оттяжки → начальная скорость стрелы; гравитация; стрела каждый кадр разворачивается по вектору скорости (имитация оперения); стрела «втыкается» в мишень (переключение в кинематику и привязка к объекту).

### 3.4 Бокс
- **Петля:** 3 раунда по 60 секунд. На «лапах»/груше загораются цели — нужно ударить **нужной рукой** с достаточной скоростью; темп растёт с каждым раундом.
- **Мотивация:** комбо-счётчик, рейтинг удара (слабый/хороший/отличный по скорости), «ответные удары» — перекладина, от которой надо уклониться (присесть/наклониться), иначе потеря комбо.
- **Физика:** скорость кулака берётся из трекинга контроллера; груша висит на шарнире (ConfigurableJoint) и раскачивается от импульса удара; вибрация контроллера пропорциональна силе удара.

### 3.5 Мини-гольф (по возможности)
- **Петля:** 5 лунок, у каждой «пар»; счёт ударов, итоговая карта.
- **Физика:** сила удара = скорость клюшки в момент касания; трение качения, уклоны, мельница-препятствие.

## 4. Общая архитектура (то, что объединяет все режимы)

```
Хаб (лобби)  ──выбор станции──►  Сцена режима
   │                                 │
   ├─ меню, рекорды, настройки        ├─ SportModeBase (машина состояний:
   │                                  │    Intro → Playing → RoundEnd → Results)
   └─ SceneLoader (загрузка с         ├─ ScoreBoard (world-space UI)
      затемнением экрана)             └─ конфиг режима (ScriptableObject)

Общие сервисы: SaveSystem (рекорды в JSON), AudioManager, Haptics (вибрация),
               VelocityTracker (оценка скорости руки), ComfortSettings (телепорт/плавное движение, поворот).
```

- **Одна сцена на режим** + хаб: проще отлаживать и объяснять.
- **Машина состояний** (`SportModeBase`) — одинаковый жизненный цикл у всех режимов, конкретный режим переопределяет только свою логику.
- **ScriptableObject-конфиги** — параметры (время раунда, массы, очки) меняются без правки кода.
- **Тестирование без шлема:** XR Device Simulator (уже есть в шаблоне) — управление «руками» мышью и клавиатурой.

## 5. Графика и ассеты (Blender, low-poly)

- Модели создаются **Python-скриптами Blender** (запуск без интерфейса: `blender -b -P script.py`) и экспортируются в FBX. Плюс для защиты: модели воспроизводимы, параметры можно показать в коде.
- Стиль: плоские цвета (flat shading), одна общая палитра-текстура → мало материалов, мало draw calls, высокий FPS в шлеме.
- Список: дорожка, шар, кегли; мяч, кольцо, щит, стойка; лук, стрела, мишени, тарелочки; груша, лапы, перчатки; клюшка, мяч, модули поля; хаб (пол, станции, табло).
- Звуки — из свободных библиотек (CC0), с указанием источников в тексте диплома.

## 8. Казуальный режим сложности (добавлено по итогам тестов в шлеме)

**Проблема.** Тесты боулинга и баскетбола в шлеме показали, что реалистичная физика в VR очень сложна для неподготовленного игрока. Причины:
- контроллер тяжелее и толще мяча;
- нет тактильного ощущения веса;
- точность броска ниже, чем в жизни.

**Решение.** В хабе появится глобальный переключатель **«Реалистичный / Казуальный»**. Он хранится в SaveSystem, рекорды ведутся отдельно для каждой сложности. Реалистичный режим остаётся «эталоном физики» для защиты. Казуальный делает игру доступной за счёт **помощи игроку**, а не за счёт отключения физики.

| Вид спорта | Помощь в казуальном режиме |
|---|---|
| Боулинг | бортики в жёлобах (bumpers), шар не уходит в жёлоб; сильнее хук |
| Баскетбол | доводка броска: скорость корректируется к баллистической траектории в кольцо; кольцо крупнее |
| Лук | траектория-подсказка, слабее гравитация и ветер, крупнее мишени |
| Бокс | ниже требуемая скорость удара, медленнее темп, больше окно попадания |

Архитектура: статический класс настроек `GameSettings.Difficulty` и параметры режимов, которые зависят от сложности (ScriptableObject-пресеты «Realistic» и «Casual»). Режимы читают пресет при старте партии.

**Аргумент для защиты.** Разделение «симуляция ↔ доступность» — стандартная практика в спортивных играх: assist-опции в автосимуляторах, аркадная и симуляционная физика в одной игре.
